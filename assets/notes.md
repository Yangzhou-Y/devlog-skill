# 项目特有规则

> 放在 `devlog/notes.md`，写日志前会被读到。只写本 skill 学不到的、这个项目特有的坑。

## 写什么

- 哪些产物不入库、证据靠什么保底
- 哪些日志/报告里的数值不可信，该看哪一份
- 术语黑话：一个词在本项目里的确切含义
- 团队约定：命名、编号、必须留痕的操作

## 示例

```markdown
- `.sim/` 与 `*.bit` 不入 git：证据靠 BUILDS.md 的校验和保底
- 布线日志里的中间时序摘要不能当签核值，只认 timing 报告表格
- “整炮”指一次完整放电，不是单炮次
- 现场操作类验证没有复现命令，日志里写“无（现场操作）”
```

## 不写什么

- 通用格式规则（在 SKILL.md 里，改了会影响所有项目）
- 任务清单（在 TASKS.md）
- 一次性事项（在日志里）
